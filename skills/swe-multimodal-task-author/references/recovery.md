# Outer-owned recovery and scope review

Handle these during the assigned run; a third supervising agent is not required.
Use supported helpers first. Read actual errors and check the installed tool version.
Keep fixes narrow, record the result in staging, and continue within the same budget.
Task technical edits still belong to the recorded inner; prose belongs to the outer.

- **Queued terminal:** ready=false is not a usable Codex session. Wait with
  inner-wait and send the task request only after ready=true. Do not paste text or
  press terminal keys while queued. inner-exit can cancel a never-started queue
  entry; it has no trace and does not satisfy authoring provenance. Do not request
  the oracle to work around a missing real author segment.
- **Optional idea references:** one PERMISSION_DENIED response is not a reason to
  repeat the same request or declare the assigned PR unavailable. Use the supplied
  PR when it establishes the required bug context. Request genuinely missing
  feature specifications, author identity or required metadata once, without
  inventing them or substituting unrelated scope.

- **Authentication:** OpenRouter judges and Codex probes use separate credentials.
  The launcher makes a live Codex preflight before either task agent starts. If a
  probe later reports expired/missing login, use worker-auth-refresh and worker-wait,
  inspect its outcome, then retry the affected check. Never print keys, change probe
  agents or copy Helix credentials to the worker. Failed calls retain their counts.
- **Approvals:** inspect the actual inner prompt and command. Approve routine task,
  staging and bridge operations already authorized by JOB.md with inner-key. Do not
  wait for another chat to do this, blindly accept menus or alter personal settings.
  The launcher scopes writable task/staging roots and network access to its children.
- **Trace saving:** rely on traceSaved and its journal evidence, not a console phrase.
  Use the documented upload-only recovery if needed. uploaded=0 can mean nothing
  remains pending. Never edit locks, journals, upload digests or Helix sync state.
- **Media/build dependencies:** inspect the kit API and pinned browser/runtime version;
  reuse the same worker and Docker cache. Repair genuine missing dependencies in
  the private capture scaffold, using supported official sources. Check actual
  frames and matching broken/working inputs. Keep capture tools outside the task.
- **Metadata/templates:** use verified author details and assigned identity. Identify
  missing inputs at the first preflight; request essential missing details once while
  continuing independent work. Do not invent a legacy Realm ID for a Helix UUID.
- **Snapshots/history:** use worker-sync and its verified path, not a manually
  assembled copy. The helper handles deltas and empty-directory cleanup. Keep a real
  base branch/ref for file-only Git transport. Treat an exported ZIP losing required
  history or a managed template mismatch as a compatibility issue; preserve bytes
  and evidence rather than inventing history or replacing managed files.
- **Verifier findings:** review the candidate, decisive trace and public contract
  before asking for an edit. Run one finite baseline comparison when scope is unclear.
  A behavior already working on starter belongs in relevant P2P. A valid repair in
  another production layer must remain accepted. Classify the result as a genuine
  gap, an invalid finding with evidence, or an infrastructure/unresolved issue.
  Have the inner save justified disputes. A local dispute remains review-required.

Use staged scripts through worker-run for recoverable task-specific execution gaps.
Repair job-local runtime helpers in staging within this job's existing authority;
shared controller source and personal configuration remain unchanged. Do not broaden
task scope, budgets, workers or permissions, change managed Helix files, or restart
the whole run to clear retry counts. If the controller itself cannot continue safely,
preserve a precise diagnostic and an incomplete handoff; do not claim recovery.

Use bounded wait helpers instead of repeated read/status/log commands. After one
coherent repair, replay affected starter/reference and saved good/bad controls in
one batch. Inspect a failing deterministic reproduction before resampling a judge.
Equivalent defaults and bounded sequential work are not defects by themselves;
require a particular timing, scheduling or cancellation policy only when the task's
public contract calls for it. Apply these rules generally, not as a list of probe
patch signatures. Reserve the job's final delivery window and report phase durations
from the generated receipts. Do not spend the full budget polishing status notes.
