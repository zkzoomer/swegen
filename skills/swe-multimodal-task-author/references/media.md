# Real media capture and category support

Use before defining or capturing attachments. Read the
[runtime capture guide](capture-kit.md), then the kit's installed README/API docs.
The controller uploads the external proprietary kit when `MEDIA_CAPTURE_KIT_DIR`
is configured. In the worker that variable points to `/opt/micro1/media-capture-kit`;
do not assume the original author's absolute local directory exists in Daytona.

Agent-operated recording of a running application on a virtual/emulated screen is
real capture. Synthetic images/video generated by diffusion or similar models are
not task evidence. Do not fake interfaces, add explanatory overlays, manipulate
settings to exaggerate the failure, or invent reporter-provided expected output.

## Capture lifecycle

1. Define the material fact the solver must notice, the genuine user sequence/input,
   and the source to capture. Screenshot static output; video an interaction/time
   sequence. Do not assume every category is a bug reproduction.
2. The kit needs a source task environment and reference patch. Before the main
   author session, prepare a disposable author-only capture scaffold from the assigned
   base/PR outside the managed task. Use a preliminary recorded session only if that
   prerequisite cannot be established there; report the ordering exception.
3. Build temporary capture tasks and run jobs outside the managed task root. The
   installed README documents direct library capture and separate Harbor workers.
   Direct capture can run in Docker inside the existing worker without extra Daytona
   credentials. Separate workers require their own executor access and budget; see
   [capture-kit.md](capture-kit.md). Use the installed API and commands.
4. For the kit's bug/fix procedure, inspect both `bug.*` and `fixed.*`, audit commands
   and `repro/run.sh`, and verify the same steps reproduce the symptom only before
   the fix. A reward of 1 checks basic artifacts, not whether media shows the bug.
5. Select solver attachments separately from private verification. Paired broken/
   working media is this workflow's default when both have a credible user-facing
   role; the assignment may choose broken-only media if the combined brief, media
   and existing interfaces still establish the outcome. Before supplying a working
   target, record who could have it and why, such as a supplied design, genuine
   reference release or authorized reference application. Rendering the gold alone
   does not establish that provenance. Keep code, logs, commentary, `repro/`, patches,
   audit output and tooling outside solver media. The kit's final-output recipe
   prefers bug-only media; do not alter or misquote it or treat either recipe as
   waiving the pipeline's realism requirement.
6. Give chosen attachments to the inner session to copy into `environment/media/`.
   The Dockerfile maps these to `/media`, outside `/app`. The outer saves its prompt
   with outer-save-text using those runtime paths.

Do not copy/crop/re-encode upstream issue media and call it a fresh capture. The kit
allows reference inspection but requires new output from the actual starting source.
Keep fixed/reference runs visually comparable. While recording, use the kit's native
input channel rather than mixing it with Playwright clicks/fills/mouse/keyboard, which
can create artificial glitches. Follow its installed rules for timing and appearance.

## Category-specific evidence

| Category | Capture source | Required decision |
| --- | --- | --- |
| Bug fix | Assigned source at its buggy commit; the real reported sequence/output | Verify bug before and absence after the fix privately; select fresh solver media with a credible role and enough information to establish the outcome. |
| Feature | A genuine supplied design/specification or authorized reference application | The media must supply a requirement absent from text/code. Do not invent a design or manufacture an authoritative target from the gold implementation. |
| Refactor | A real structural diagram/document/specification that materially constrains the change | An app screenshot alone does not define an internal restructuring. Report a task with no meaningful media input as unsuitable. |
| Performance | Real workload/state/interaction exposing the problem | Pair author evidence with reliable measurements and correctness. Do not artificially slow the program or grade only apparent video speed. |

The kit and bundled golden prompts are bug-fix focused. Other capture branches need
tool support and actual source material before claiming they work. Missing designs,
unavailable services, failed reproduction, or no meaningful visual requirement are
explicit unsupported outcomes. Preserve evidence and report what input/capability is
missing; do not redefine the task to manufacture a successful capture.

A working capture can be solver media when its reference basis exists independently
of our chosen repair and its role is honest. A new capture of a genuine release or
authorized reference program is acceptable evidence of that basis; an author-created
expected result is not made authoritative by labeling it "working." Keep gold-derived
comparisons private when no legitimate solver-facing reference exists. Never present
such output as a supplied feature design or claim provenance it does not have.

## Inspect and package

Open actual frames at useful resolution and in temporal order. Verify duration,
legibility, relevant before/action/after state, and that required facts survive normal
sampling. The shipped video workflow extracts frames; do not rely on audio alone.

Every attachment must exist, be nonempty, have a purpose, and be named in the prompt
at `/media/...`. Avoid whitespace, quotes, and brackets in filenames. Captured guidance
mixes MB/MiB for 25-per-file and 100-total limits; check current enforced byte limits
and stay comfortably below both interpretations. Use `Recreated Media` for new captures
and accurate visual role/format metadata.

Inspect the actual built image and uploaded version rather than assuming local files
prove availability. Distinguish missing media from a judge input missing the gold patch.
Cached manifests and archive timestamps are not fresh server verification.

Run media ablation on the final prompt version. Correct diagnosis without media is
also a necessity finding even when the patch fails. A static media-necessity judge or
an older prompt's ablation cannot certify the current task.
